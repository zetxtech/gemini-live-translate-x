```

含义：文字只能原位或向左移动，不允许向右移动。

滚动启动规则：

1. 当前译文第一次出现时，`translateX = 0`。
2. 当前译文从空变为非空后，至少 `500ms` 内不滚动。
3. 未超过容器宽度时，不滚动。
4. 超过容器宽度时，先保持开头，再平滑向左移动到可读位置。
5. 历史行不横向滚动；历史行过长时可以使用裁剪、淡出或缩小字号，但不应动态滚动。

## 动画设计

动画必须服务于信息层级，不承担业务状态修正。

### 当前行更新

当前译文追加文字时，不播放进入动画，只更新文本并按滚动规则处理。

当前译文从空到非空时，可以淡入，但不能位移。

### 当前句进入历史

同一个句子从 current 迁移到 history 时，不能重新从当前行位置上浮一次。建议做法：

1. 当前行文本保持稳定。
2. 下一句到来时，显示帧中旧句变为 history row，新句变为 current row。
3. 容器做一次轻微 layout transition，旧句透明度和字号变为历史样式。
4. 不给旧句播放独立 `entering` 动画。

### 新历史行进入

只有未曾作为当前句显示过的历史行，才允许播放历史进入动画。正常实时字幕中几乎不应出现这种情况。

### 退出动画

历史超过可见行数时，最旧历史行可以淡出。退出 clone 必须满足：

1. 不参与 hit area。
2. 不参与后续 frame diff。
3. 动画结束后强制移除。
4. 不继承滚动状态。

## 设置规则

设置应影响显示帧层，而不是直接让渲染层临时判断业务语义。

### 双语模式

双语模式只影响当前区：

1. 当前译文显示。
2. 当前原文显示在当前译文下方。
3. 历史区仍只显示译文。

### 历史行数

`historyRows` 只决定显示帧层最多输出多少条历史译文。

建议保留：

```ts
historyRows: 0 | 1 | 2
```

在双语模式下，如果窗口高度不足，可以自动降级为 1 行历史，但这个降级应在显示帧层明确记录并输出调试日志。

### 对齐

当前实现强制左对齐。如果未来恢复居中或右对齐，必须保证横向滚动算法仍以可读开头为准。

建议第一版只支持左对齐，避免把视觉偏移问题复杂化。

## Tauri 窗口约束

真实悬浮窗口是最终显示环境。设计必须承认浏览器页和 Tauri WebView 的差异。

Tauri 层需要提供或记录：

1. 当前字幕窗口外部尺寸。
2. 当前 WebView 可视尺寸。
3. DPI scale factor。
4. 是否锁定。
5. 当前 hit area。

调试模式下，字幕窗口应能显示布局诊断信息，例如：

```text
frame=128 rows=3 scale=1.12 stage=1120x180 currentX=0 overflow=false
```

诊断信息必须可关闭，不应出现在普通使用中。

## 测试设计

测试分三层：状态机测试、显示帧测试、真实窗口视觉测试。

### 状态机测试

输入事件序列，断言 `SubtitleState`。

必须覆盖：

1. 普通短句追加。
2. 强标点在片段末尾。
3. 强标点后有长尾巴。
4. 强标点后有短尾巴。
5. 短尾巴等待后合并。
6. 短尾巴超时后继续显示但不提交历史。
7. 连续标点。
8. 单独结束信号。
9. 原文先于译文到来。
10. 原文和译文交错到来。

### 显示帧测试

输入 `SubtitleState + SubtitleSettings`，断言 `CaptionFrame.rows`。

必须覆盖：

1. 双语历史只显示译文。
2. 双语当前显示译文和原文。
3. 单语当前只显示译文。
4. `historyRows = 0` 不输出历史。
5. 空状态只在真正无内容时出现。
6. 不输出空白占位行。
7. current 到 history 的同一句 key/lifecycle 正确。

### 渲染测试

渲染测试检查 DOM 和几何信息。

必须断言：

1. 当前译文第一帧 `translateX = 0`。
2. 任意时刻 `translateX <= 0`。
3. 短文本不会向右偏移。
4. 长文本 500ms 内不滚动。
5. 当前译文行的 bounding box 不被 stage 裁切。
6. 文字描边和阴影有垂直安全区。
7. 历史行不包含原文。
8. 切句迁移时同一句不出现两次 entering。

### 真实窗口视觉测试

必须在 Tauri dev 窗口中验证，不只依赖浏览器页。

建议测试矩阵：

| 模式 | 历史行 | 文本长度 | 期望 |
| --- | --- | --- | --- |
| 单语 | 0 | 短句 | 首字不右移，不裁上沿 |
| 单语 | 0 | 长句 | 先静止，后左滚 |
| 双语 | 0 | 短句 + 原文 | 当前译文主显示，原文在下方 |
| 双语 | 1 | 切句 | 历史只中文，当前不空 |
| 双语 | 1 | 长句 | 中文不裁切，英文不挤掉中文 |
| 单语 | 2 | 多句 | 不连续快速刷行 |

视觉测试通过标准：

1. 截图中当前译文完整可见。
2. 当前译文上沿、描边和阴影不被裁。
3. 第一批文字不向右跳。
4. 同一句从当前到历史没有二次上浮感。
5. 历史中没有英文原文。

## 日志设计

字幕系统应提供结构化调试日志，而不是只输出自然语言。

建议日志格式：

```text
[subtitle] event translation-delta text="会议" at=12345
[subtitle] state current id=3 text="会议" pending=none history=1
[subtitle] boundary kind=terminal index=8 action=wait-next
[subtitle] commit id=3 reason=next-text next="然后"
[subtitle] frame rows=history:t#3,current:t#4,current:o#4
[subtitle] layout row=current:t#4 x=0 overflow=false clipped=false
```

日志要能回答这些问题：

1. 新片段什么时候到来。
2. 当前句文本是什么。
3. 为什么准备切句。
4. 为什么真正提交历史。
5. 是否等待短尾巴。
6. 本帧实际显示了哪些行。
7. 当前行是否发生横向滚动。
8. 是否检测到裁切风险。

## 实施计划

建议分阶段重构，避免一次性替换后难以定位问题。

### 第一阶段：建立纯数据模型

新增字幕状态模块和显示帧模块，不改现有 UI。

目标：用单元测试证明切句和显示帧符合需求。

交付物：

1. `subtitle-model.ts`
2. `subtitle-frame.ts`
3. 状态机测试
4. 显示帧测试

### 第二阶段：替换推送协议

`main.ts` 不再直接发送 `{ history, curO, curT }`，而是发送 `CaptionFrame` 或发送足够明确的 `SubtitleState`。

目标：让 `subtitles.ts` 不再临时判断历史、当前、原文和空状态。

### 第三阶段：重写渲染层 DOM

用新的 DOM 结构替换当前 `.line-group/.line/.line-text` 体系。

目标：业务状态不再藏在 DOM class 里，横向滚动和垂直布局彻底分离。

### 第四阶段：重写滚动与动画

实现新的横向滚动约束和生命周期动画。

目标：首字不右移、长句先停留、同一句不重复上浮。

### 第五阶段：加入真实窗口测试流程

增加固定测试场景，输出 Tauri 窗口截图和几何日志。

目标：以后修改字幕系统时，不能只靠构建通过作为结论。

## 必须保持的不变量

以下规则是新系统的硬约束，任何实现都不能破坏：

1. 历史行永远不显示原文。
2. 当前译文第一次出现时，横向位移必须是 0。
3. 任意字幕文本的横向位移不得大于 0。
4. 没有下一句译文时，不提交当前句到历史。
5. 单独标点不能成为独立历史句。
6. 短尾巴不能快速单独成为历史句。
7. 当前句进入历史时，同一句不能再次播放明显上浮动画。
8. 渲染层不能用空白文本伪装业务状态。
9. 字幕行自身不得裁掉文字上沿、描边或阴影。
10. 构建通过不等于验收通过，真实 Tauri 窗口视觉测试必须通过。

## 结论

新的字幕系统应从“临时 DOM 修补”转为“数据状态驱动”。

关键变化是：切句由状态机决定，显示由帧模型决定，渲染层只负责把帧模型稳定画出来。这样可以把用户需求中的稳定、可读、不过度跳动，转化成可以测试和长期维护的不变量。
